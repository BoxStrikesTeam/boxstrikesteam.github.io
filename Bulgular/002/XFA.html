This script reads the embedded XML, extracts the fragments via XPath, concatenates them, and executes the decoded reverse shell.

# Concatenate fragments

# Decode Base64

# Execute as ScriptBlock

4. Why This Is a Defense Evasion Technique

The XFA technique is designed to evade detection by modern EDR/AV solutions for the following reasons:

  • No deserialisation: Unlike many PowerShell‑based attacks that rely on ConvertFrom-CliXml or PSSerializer.Deserialize, this method uses only [xml] and XPath. These are standard, legitimate operations that are rarely flagged as suspicious.
  • Payload fragmentation and encryption: The Base64 fragments stored in the XML are individually harmless. Static analysis does not detect the complete command until all fragments are concatenated and decoded in memory.
  • Memory‑only execution: The final command is assembled and executed entirely in memory. No executable file is written to disk, bypassing file‑based scans.
  • Blending with normal activity: XML parsing, string concatenation, and Base64 decoding are common administrative tasks. This makes it difficult for behavioural analysis to distinguish the attack from routine operations.
  • Cross‑version compatibility: By avoiding deserialization, the technique works on both PowerShell 5.1 (the default on most Windows systems) and PowerShell 7.x.

5. Mitigation Recommendations

To defend against this and similar techniques, the following measures are recommended:

  • Monitor XML parsing activity: Look for PowerShell processes that read XML files or use [xml] casts followed by dynamic execution (ScriptBlock::Create).
  • Enable ScriptBlock logging: Use PowerShell’s ScriptBlock logging (Event ID 4104) to capture the full command before execution.
  • Restrict PowerShell Language Mode: Use ConstrainedLanguage mode to prevent dynamic code execution from deserialized or parsed data.
  • Implement AppLocker / WDAC: Limit script execution to signed or approved scripts only.
  • Keep AMSI updated: Ensure AMSI is active and up‑to‑date in all PowerShell sessions.

6. Conclusion

The XPath Fragment Assembly (XFA) technique demonstrates how seemingly benign operations—XML parsing, string manipulation, and Base64 decoding— can be chained to create a functional and evasive payload delivery method. By avoiding deserialization, the technique remains compatible with older PowerShell versions and leaves a minimal forensic footprint.

This research highlights the importance of understanding how attackers can abuse legitimate system features. Defenders are encouraged to implement the mitigation strategies outlined above and to consider behaviour‑based detection rules that look for unusual combinations of XML parsing and dynamic execution.
