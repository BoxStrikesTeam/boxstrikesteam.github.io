XPath Fragment Assembly (XFA) – A Defense Evasion Technique Using XML and PowerShell
Published: 9 August 2026 Author: BoxStrike Research Version: 1.3 Classification: Public

1. Introduction

This report describes a defense evasion technique for Windows environments that abuses PowerShell’s ability to parse XML and execute dynamic code. The technique, named XPath Fragment Assembly (XFA), allows a malicious payload to be split into Base64-encoded fragments, stored inside a seemingly harmless XML structure, and then reassembled and executed without any deserialization calls such as ConvertFrom-CliXml or PSSerializer.Deserialize.

The core idea is to use legitimate XML parsing (via [xml] and XPath) to extract the fragments, concatenate them, decode the resulting Base64 string, and finally execute the payload as a PowerShell ScriptBlock. This approach is designed to blend in with normal system administration activities, making it harder for EDR/AV solutions to flag the activity as malicious.

2. Methodology

The XFA technique consists of the following steps. All operations are performed in memory; no files are written to disk (except the initial XML if delivered that way).

  1. Payload preparation: The attacker takes the desired PowerShell command (e.g., a reverse shell) and converts it to a Base64 string using [Convert]::ToBase64String().
  2. Fragmentation: The Base64 string is split into multiple fragments. The total length of all fragments must be a multiple of 4 to satisfy Base64 encoding requirements. In this PoC, we use 13 fragments with a total length of 708 (708 mod 4 = 0).
  3. XML embedding: Each fragment is placed inside an <S> tag within a valid CLIXML‑style XML structure. The XML is then either saved to disk or embedded directly in the PowerShell script (here‑string).
  4. Delivery: The XML is delivered to the target system (e.g., via email, web download, or as a script attachment).
  5. Parsing (XPath): On the target, the XML is read using Get-Content and cast to [xml]. The expression $xml.Objs.Obj.S extracts all fragments as a string array. No deserialization occurs at this stage.
  6. Assembly: The fragments are concatenated using -join '' to reconstruct the original Base64 string.
  7. Decoding and execution: The combined Base64 is decoded with FromBase64String, and the resulting command is converted to a ScriptBlock using [scriptblock]::Create() and executed with the & operator.

The key to evasion is that every step uses legitimate, commonly‑used PowerShell features. Reading XML, extracting nodes via XPath, and concatenating strings are routine activities that security products typically do not flag as anomalous.

2.1. Why Base64 Length Matters

A common mistake in earlier versions of this PoC was using fragments with a total length of 733 (733 mod 4 = 1). Base64 strings must have a length that is a multiple of 4 (mod 0, 2, or 3 is acceptable, but mod 1 is invalid). The corrected version uses fragments that sum to 708 (708 mod 4 = 0), ensuring successful decoding.

3.2. Execution Script (XPath, No Deserialization)

This script reads the embedded XML, extracts the fragments via XPath, concatenates them, and executes the decoded reverse shell. 

# Parse XML as XmlDocument (no deserialization)
$xml = [xml]$xmlPayload

# XPath: get all <S> contents
$fragments = $xml.Objs.Obj.S

# Concatenate fragments
$combinedBase64 = $fragments -join ''

# Decode Base64
$fullCommand = [System.Text.Encoding]::UTF8.GetString([System.Convert]::FromBase64String($combinedBase64))

# Execute as ScriptBlock
& ([scriptblock]::Create($fullCommand))

4. Why This Is a Defense Evasion Technique

The XFA technique is designed to evade detection by modern EDR/AV solutions for the following reasons:

  • No deserialisation: Unlike many PowerShell‑based attacks that rely on ConvertFrom-CliXml or PSSerializer.Deserialize, this method uses only [xml] and XPath. These are standard, legitimate operations that are rarely flagged as suspicious.
  • Payload fragmentation and encryption: The Base64 fragments stored in the XML are individually harmless. Static analysis does not detect the complete command until all fragments are concatenated and decoded in memory.
  • Memory‑only execution: The final command is assembled and executed entirely in memory. No executable file is written to disk, bypassing file‑based scans.
  • Blending with normal activity: XML parsing, string concatenation, and Base64 decoding are common administrative tasks. This makes it difficult for behavioural analysis to distinguish the attack from routine operations.
  • Cross‑version compatibility: By avoiding deserialization, the technique works on both PowerShell 5.1 (the default on most Windows systems) and PowerShell 7.x.

5. Mitigation Recommendations

To defend against this and similar techniques, the following measures are recommended:

  • Monitor XML parsing activity: Look for PowerShell processes that read XML files or use [xml] casts followed by dynamic execution (ScriptBlock::Create).
  • Enable ScriptBlock logging: Use PowerShell’s ScriptBlock logging (Event ID 4104) to capture the full command before execution.
  • Restrict PowerShell Language Mode: Use ConstrainedLanguage mode to prevent dynamic code execution from deserialized or parsed data.
  • Implement AppLocker / WDAC: Limit script execution to signed or approved scripts only.
  • Keep AMSI updated: Ensure AMSI is active and up‑to‑date in all PowerShell sessions.

6. Conclusion

The XPath Fragment Assembly (XFA) technique demonstrates how seemingly benign operations—XML parsing, string manipulation, and Base64 decoding— can be chained to create a functional and evasive payload delivery method. By avoiding deserialization, the technique remains compatible with older PowerShell versions and leaves a minimal forensic footprint.

This research highlights the importance of understanding how attackers can abuse legitimate system features. Defenders are encouraged to implement the mitigation strategies outlined above and to consider behaviour‑based detection rules that look for unusual combinations of XML parsing and dynamic execution.
